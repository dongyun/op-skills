# General Store 播客发布

使用本技能目录下 `scripts/publish_podcast.py`。Python 3.10+、httpx；有 ffprobe 时本地检查音轨与时长，服务端负责完整媒体校验。本机可复用 `/Users/dongyun/work/apple_app/general-store/services/api/.venv/bin/python`；其他环境可用 `uv run --with 'httpx>=0.28,<1' python`。

## 执行流程

1. 读取用户指定输出目录的 `delivery.json`、正式稿和质量记录。默认选 `audio.mp3`，文字稿优先 `podcast_script_tts.md`，缺少时选正式稿；不用 `sample.mp3`、WAV 或草稿代替成品。默认标题取 `delivery.json.topic`，简介取正式稿的“本集一句话”。封面按 `--cover` 明确指定 → 素材目录的 `cover.png/.jpg/.jpeg`、`podcast_cover.png/.jpg/.jpeg` → 技能内置 `assets/default-cover.png` 的顺序选择。提供的封面无效时停止，不用默认图掩盖错误。默认图会复制到计划旁的 `<计划名>.assets/` 并记录哈希，后续与音频、文字稿一起上传和发布。
2. 确定目标源站、凭据来源和所属节目。凭据只读用户提供的路径、明确的凭据引用或环境变量，不广泛搜索 Secret。脚本支持环境变量、JSON、简单 env 文件及 Key/Secret 两行文本；不要把值放入工具参数、聊天、命令行、回执或仓库。凭据文件建议权限 600，不执行 `source`。
3. 使用 `list-shows` 查询真实节目。优先追加已存在且已发布、名称与内容相符的节目；歧义时询问。新建节目必须有确定的名称和作者，不能为每集无意新建一个节目。已有节目未发布时停止，单独处理其发布意图。
4. 用 `prepare` 在可写工作目录保存计划；检查源站、节目、标题、简介、输入文件及 SHA-256。发布前只读查询同名单集，已有条目先核对，避免因新计划重复发布。
5. 用户已明确授权此目标发布时直接运行 `publish --execute`，不重复确认。仅要求制作技能或本地测试时，先做本地验证；未经授权不把测试扩展为线上发布。目标或凭据未明确时继续完成本地工作，再补齐缺失信息。
6. 回读验证后报告节目 ID、单集 ID、发布快照 ID、回执路径及未验收部分。Key 仅能验证管理接口，不能证明 App 播放/下载成功；音频技术验收也不能替代人工听审。

详细命令及接口约束见 [references/publishing.md](references/publishing.md)。

## 续跑与边界

- 默认封面适用于新生成的发布计划；恢复旧计划时按原内容执行，不修改历史计划或已发布快照。
- 同一任务一直使用原计划、原回执、相同 API Key 和原始文件。脚本对计划和 API Key 绑定哈希，写入前核对文件哈希，并持久化每步请求意图、结果；进程重启复用步骤幂等键。`prepare` 默认生成 UUID 任务 ID；不要为另一任务手动复用它。
- 已成功步骤不重复上传或创建；请求已提交但回执丢失时以同一键恢复。凭据轮换后先核对旧任务远端结果，不自动改用新 Key 重放。
- 401/403、409、422 等立即停止。网络、429、5xx 每步最多四次尝试；耗尽后报告已有进度和回执，不循环重启。409 不自动改版本或覆盖远端内容。
- `verify` 只读远端并更新本地验证记录。单集下架、被修改或发布指针变化时报告当前不一致，不以历史成功回执代替当前状态，也不擅自恢复。
- 此工具只创建/发布新单集；不修改、下架、删除已有内容，不创建或撤销 API 密钥。

## 本地验证

`python -m unittest discover -s <skill目录>/tests -v` 验证重试、回执续跑、输入变更与错误停止行为。真实发布必须另行核验，不能把测试桩结果称为生产通过。
