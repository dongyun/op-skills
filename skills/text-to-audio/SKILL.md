# 文字稿转音频

使用本技能自带的 Python 脚本、edge-tts 和 FFmpeg。保留原稿，生成清洁朗读稿、分段音频、完整 MP3/WAV 和验收记录。仅制作技能或修改技能时，不执行配音或生成封面。

## 先补齐用户的选择

读取指定文稿及本次对话中已经明确的偏好。单人文章使用一个朗读者；多角色稿保留现有角色、顺序及台词，不擅自改写成双主持。续作沿用已保存且未改变的选择。

**没有指定音色时，必须展示选择框并等待用户实际提交，不能直接使用项目默认声线。** 优先使用 `request_user_input_async`；其返回立即结束不代表用户已经回答。等候时可整理文稿、核对本地依赖，不开始声音请求。预选项和超时都不视为选择。只有用户明确说“你选”“用默认”时才可代选，并记录具体映射。

选项使用好理解的描述，例如「淳厚男声」「清朗男声」「甜美女声」「活泼女声」。界面不以 `zh-CN-…Neural` 作为选项名。性格词是选型描述，不代表经过人工试听，也不是引擎的情绪参数。映射及提问范例见 [references/voices.md](references/voices.md)。

- 单人稿：一次询问音色和是否生成封面，只提问尚未确定的项目。
- 双主持或多角色：按角色分别询问缺少的音色；明确“女声甜美、男声淳厚”已经足够，不再重复询问。
- 已指定准确声线 ID 或可明确映射的中文描述：直接采用。只有“男声”这类宽泛要求仍展示适合的男声选项。
- 封面选择：「仅生成音频」「音频＋主题封面」。用户已明确要/不要封面则不问。没有回复封面偏好时可以完成已确定的音频，封面保持待选择，不擅自生成；整项请求仍记为待选择，不能宣称全部完成。
- 当只有 Plan 模式的 `request_user_input` 可用时遵守其选项数量限制，必要时先选男/女声，再选风格。交互工具确实不可用时，改用简短编号选项等用户回复，不伪称已经弹出选择框。

## 执行

1. 新任务使用用户指定目录；未指定时在当前工作区创建 `outputs/日期/稿名/audio-v1/`，已存在则递增版本。保留原稿副本；准备 `podcast_script.md`，其中 `## 正文` 到下一个二级标题之间仅含 `角色名：台词` 和可选三级章节标题。单人稿用 `朗读者：`；只调整格式，不增删正文。正文外的参考资料、配音说明不朗读。内联停顿与朗读改写详见 [references/audio-workflow.md](references/audio-workflow.md)。
2. 把实际选择保存为 `audio_settings.json`。每个角色必须有明确声线，封面选择单独记录。工具不会填默认声线。检查 Python、edge-tts、FFmpeg 的 libmp3lame 和 ffprobe；先看脚本 `--help`，只使用已实现接口。
3. 创建 `audio_manifest.json`，审阅逐段 `text`、`spoken_text`、角色和停顿，导出 `podcast_script_tts.md`。只让清单中的 `spoken_text` 进入引擎。记录朗读改写，再运行 `--review-text` 登记本次内容核对；这只代表配音文本准备通过，不伪造独立编辑评分。所在项目有文字门禁时，复用对应版本的证据，缺失则按项目规则补齐后才能配音。
4. 每批新增请求前，脚本查询声音列表并核对所有选中声线。不可用时保留结果，让用户选择可用替代；不偷偷换声线、服务或付费 API。每次请求 45 秒超时，累计最多三次；续作不重置预算。
5. 首次任务或参数变更时，选覆盖所有角色、专名和数字的实际段落生成样段，独立技术核验后继续全稿。短稿可以整体作为样段；不自动添加一次用户批准环节。样段通过不代表人工听感通过。
6. 合成余下片段，完整拼接并运行独立脚本 `verify_audio.py`。逐段缓存按指纹、哈希和解码校验；已失败的片段不删台词、不以静音补齐。输入不变时原目录续作；改稿、声音、参数时新建版本目录，旧成果保留。只改顺序/停顿也需重新拼接验收。
7. 用户选择封面时，根据稿件主题使用内置图像生成工具生成一张方形主题封面；见 [references/cover.md](references/cover.md)。封面可与配音独立推进，失败不影响保存音频，但不能把用户要求的全套交付记为完成。
8. 整合 `quality_report.md` 和 `delivery.json`，列出文字准备、项目文字门禁（适用时）、音频技术、封面和人工听审状态。音频技术通过且所选封面完成，才记本次交付 `COMPLETE`。未逐段人工试听始终写 `human_listening_status: NOT_TESTED`。

详细命令、输入格式和续作方式见 [references/audio-workflow.md](references/audio-workflow.md)。不要求普通短稿达到播客项目的 12–18 分钟；只有用户或当前项目明确要求时才设置目标时长。不通过大幅变速凑时长。

## 交付

用绝对路径提供 MP3 播放入口、WAV 下载、清洁稿、清单、质量报告；有封面时直接展示图片并提供文件链接。报告实测时长、实际音色、技术验收及人工听审状态。失败时列出缺失片段/封面和续作目录，不把样段称为成品。

默认本地交付；发布、上传或发送给他人需要相应授权。此技能不会调用发布技能，也不会继承某次历史重试的额外额度。
